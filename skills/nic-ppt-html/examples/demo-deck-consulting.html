原子化技能应按需安装，而不是整仓灌入上下文

NicSkills 用脚本优先的小技能，去掉 Agent 开发链路里的确定性摩擦。

architecture · consulting + project-brand · 2026-08-13

Agenda

本材料回答三个决策问题

  • 为什么拆成 nic-* 原子技能，而不是巨型提示词包
  • 现有技能如何形成「输入 → 产物 → 预览」闭环
  • 发布门槛是什么，下一步优先做什么
Problem

摩擦集中在确定性步骤，而不是模型本身

  • file:// 预览被 IDE 拒绝，临时 server 易留僵尸进程
  • 图表 / 报告 / 截图路径散落，难以复用与归档
  • 全仓安装技能会污染上下文窗口
Bottom line: 需要可安装、可组合、输出目录统一的原子技能。
Positioning

一个技能只做一件事；能脚本化的不靠临场发挥。

Brand NicSkills · Prefix nic- · Install npx skills add nickylin/NicSkills --skill nic-xxx

Overview

技能协作形成可预览的品牌产物闭环

Layers

三层职责分离，避免技能互相抢活

Deterministic

端口、本地 HTTP、主机探测梯子 — 放进 scripts/。

Instruction routers

主题、报告结构、PPT 叙事 — 写在 SKILL.md。

Host capabilities

GenerateImage / Browser MCP / Canvas — 技能只做路由与约束。

Artifacts

运行产物进 nic-skills-artifacts/；README 媒体进 docs/。

Principles

发布前必须通过统一质量门

  • Atomic · Script-first · Progressive disclosure
  • Dogfood first · On-demand install · No private leakage
  • 新技能附 README promo：icon 128 / diagram 640 / banner 720
Install

单技能安装应成为默认路径

# 安装 PPT HTML 技能
npx skills add nickylin/NicSkills --skill nic-ppt-html

# 本地 dogfood
ln -sfn "$(pwd)/skills/nic-ppt-html" ~/.cursor/skills/nic-ppt-html
